<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client ↔ Supabase API | Unauthenticated requests use anon key; RLS enforces read-only |
| Database ↔ External | Supabase manages transport security (TLS); no PII transmitted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Public read via RLS | mitigate | RLS policy allows SELECT for anon; Phase 04 adds auth middleware to gate sensitive operations |
| T-03-02 | Tampering | Direct database writes via anon key | mitigate | RLS blocks all writes without authenticated role; Phase 04 middleware validates password before granting write access |
| T-03-03 | Denial of Service | Large result sets from public SELECT | accept | Phase 04 adds rate limiting; pagination implemented in CRUD endpoints |
| T-03-04 | Information Disclosure | Schema reflection | accept | Database schema is implementation detail; API shape is not secret; published in docs/pdi-schema.sql |

</threat_model>
