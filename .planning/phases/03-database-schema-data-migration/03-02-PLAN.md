   - Serialize `requirements` array to JSONB

2. **seedMilestones(milestones: Milestone[])**:
   - Map `milestones` to Supabase insert format
   - Serialize `objectives` and `unlockedRequirements` to JSONB
   - Convert `relatedSkills` and `relatedResources` to UUID arrays

3. **seedProjects(projects: Project[])**:
   - Map `projects` to Supabase insert format

   - Map `resources` to Supabase insert format
   - Handle `category` hierarchy (category, parentCategory, subCategory)

5. **seedPersonalInfo(info: PersonalInfo)**:
   - Insert/UPSERT single personal_info record
   - Convert date strings to ISO format for Supabase timestamp fields

Each function:
- Uses `createClient()` from lib/supabase/client.ts (service_role for seeding)
- Returns `{ count: number, errors: string[] }`
- Logs progress with `console.log`
- Includes error recovery (continues on individual row failure, collects errors)

Export all functions as named exports.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Script ↔ pdiData.ts | Local file read (no security risk) |
| Script ↔ Supabase | Service role key required; migration runs in trusted environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Tampering | Migration script modifies source data | mitigate | Script reads pdiData.ts only (no writes), backup created before any modifications |
| T-03-06 | Information Disclosure | Backup contains sensitive PII (personalInfo) | accept | Backup stored locally, not in version control (.gitignore includes backups/), service_role access only |
| T-03-07 | Denial of Service | Migration locks tables | mitigate | Use UPSERT (INSERT ON CONFLICT) to minimize locking; migration is one-time operation |
| T-03-08 | Elevation of Privilege | Service role key exposed in logs | mitigate | Script logs only summary counts, never outputs raw data or error messages containing PII |

</threat_model>
