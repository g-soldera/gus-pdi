  <action>
1. **Atualizar `package.json`:**
   - Remover de `devDependencies`: `vite`, `@vitejs/plugin-react`, `vite-plugin-*` (qualquer variante).
   - Remover arquivo `vite.config.ts` após análise de se há algo a preservar.
   - Adicionar `next` (latest stable 15.x) às `dependencies`.
   - Atualizar scripts: `"dev": "next dev"`, `"build": "next build"`, `"start": "next start"`, `"lint": "next lint"`.

2. **Criar `next.config.ts`:**
   ```typescript
   const securityHeaders = [
     { key: 'X-Content-Type-Options', value: 'nosniff' },
     { key: 'X-Frame-Options', value: 'DENY' },
     { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
     { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
   ]

   export default {
     async headers() {
       return [{ source: '/(.*)', headers: securityHeaders }]
     },
   }
   ```

3. **Atualizar `tsconfig.json`:**
   - Garantir `"moduleResolution": "bundler"` (ou `"node16"` — o que Next.js 15 exige).
   - Manter path alias `"@/*": ["./src/*"]`.
   - Adicionar `"include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"]`.
   - Remover referências a `vite/client` se houver.

4. **Criar `app/layout.tsx` (root layout):**
   - Importar ThemeProvider existente de `@/app/contexts/ThemeContext` (marcar como `'use client'` se necessário).
   - Incluir `<html lang="pt-BR">`, `<body>` com `className` de fonte existente.
   - Importar CSS global (`@/app/globals.css` ou equivalente existente).
   - Incluir `<Toaster />` do `sonner` (já instalado).

5. **Criar `app/page.tsx` (landing `/`):**
   - Página minimalista Server Component.
   - Conteúdo: título ("gus.pdi"), subtítulo breve, dois links: `<Link href="/feedback">Deixar feedback</Link>` e (sem destaque visual) `<Link href="/pdi">Dashboard</Link>`.
   - Sem autenticação, sem redirect.

6. **Criar `app/pdi/page.tsx`:**
   - Marcar `'use client'` (pois o dashboard usa hooks React amplamente).
   - Importar e renderizar o componente `App` atual (ou equivalente — o conteúdo completo do `src/app/App.tsx`).
   - Sem alterações nos componentes filhos.

7. **Criar `app/pdi/layout.tsx`:**
   - Layout específico do PDI se necessário para isolar contextos (ex: se ThemeProvider precisar estar apenas aqui).
   - Pode ser um pass-through se o root layout já cobrir.

8. **Criar `app/feedback/page.tsx`:**
   - Placeholder simples: `<main><h1>Feedback</h1><p>Formulário em breve.</p></main>`.
   - Será substituído na Wave 3.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Vite config → Next.js config | Perda de plugins Vite não portados. Mitigação: auditar vite.config.ts antes de remover. |
| ThemeContext (Client) → RSC | Providers React devem ser Client Components; RSC não suporta Context. Mitigação: `'use client'` no provider. |
| Path alias @/* | tsconfig deve declarar o alias corretamente para Next.js resolver. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Information Disclosure | /pdi URL | Low | Accept | Proteção por obscuridade; sem dados sensíveis servidos pelo servidor. |
| T-02-02 | Tampering | next.config.ts headers | Low | Mitigate | Security headers reduzem surface de clickjacking e MIME sniffing. |
